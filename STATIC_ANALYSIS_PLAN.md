# План строгой типизации и PHPStan

## Область

Анализируется и типизируется поддерживаемый PHP-код основного проекта:

- `app/`;
- `routes/`;
- `config/`;
- `bootstrap/app.php` и `bootstrap/providers.php`;
- `public/index.php`;
- `tests/`.

Исключаются `vendor/`, сгенерированные cache/compiled view и `naive-run/`.

## Этапы

1. Установить PHPStan как dev-зависимость и зафиксировать точную команду/версию в
   `sessions/TOOLS.md`.
2. Создать `phpstan.neon` с начальным уровнем 6 и перечисленными путями без
   baseline и широких `ignoreErrors`; фактически достигнут level 8.
3. Добавить Composer script `analyse` для воспроизводимого запуска.
4. Добавить `declare(strict_types=1);` во все поддерживаемые PHP-файлы.
5. Проверить сигнатуры методов, функций и callbacks: типы аргументов, возврата,
   свойств и содержимое array PHPDoc/generics там, где PHP не позволяет выразить
   форму массива нативно.
6. Запускать PHPStan, исправляя причины ошибок. Повысить уровень выше 6 только если
   он проходит без маскирующих suppressions и несоразмерных framework-обходов.
7. Запустить PHPUnit, Pint, PHPStan и реальный HTTP smoke test, затем провести
   независимый аудит и обновить журнал/STATE.
8. Сделать отдельный коммит, не включая `docker-compose.yml`.

## Согласованное решение

Пользователь выбрал только прямую dev-зависимость `larastan/larastan`; совместимый
`phpstan/phpstan` устанавливается транзитивно. Это позволяет анализатору понимать
Laravel container, фасады и helpers без дублирования прямых требований Composer.

## Критерии готовности

- PHPStan запускается одной командой и завершается без ошибок.
- Зафиксирован фактически достигнутый уровень.
- В поддерживаемых PHP-файлах присутствует `declare(strict_types=1);`.
- Все методы/функции/callbacks имеют доступные нативные типы аргументов и возврата.
- Формы массивов уточнены PHPDoc там, где это полезно анализатору.
- PHPUnit и Pint остаются зелёными; публичный API не меняется.
