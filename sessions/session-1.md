## Размышления

Папка оказалась не готовым backend-проектом, а комплектом ДЗ: код отсутствовал,
а `SPEC.md`, Часть II `AGENTS.md` и журнал были шаблонами. Поэтому писать Laravel-код
сразу нельзя: обязательный порядок курса требует сначала согласовать спецификацию и
план.

Из предложенных тем выбрали список задач: он покрывает фильтрацию, изменение данных,
валидацию и ошибочные сценарии без лишнего объёма. Авторизация и несколько
пользователей отвергнуты как не относящиеся к цели задания. Согласованы пять
эндпоинтов, свободные переходы между тремя статусами, необязательный срок и строгий
запрет неизвестных полей.

Первоначально был предложен `max(id) + 1` одновременно с обещанием не использовать
удалённые ID повторно. Это противоречие заметили до реализации: после удаления
максимального ID номер использовался бы снова. Решение заменено на хранилище с
монотонным `next_id` и массивом `tasks`.

Для ошибок сначала рассматривался возврат только первой ошибки валидации. Пользователь
выбрал возврат всех ошибок, поэтому контракт содержит массив `details`.

Первый Git-коммит сделали до заполнения журнала, чтобы сохранить исходный комплект
буквально до наших правок. Это осознанное отступление от требования записывать промпты
сразу. После просьбы пользователя root-коммит переписан: `docker-compose.yml` удалён
только из индекса и остался на диске неотслеживаемым.

## Использованные инструменты

| Инструмент | Действие | Зачем |
|---|---|---|
| `rg`, `sed`, shell | Осмотр структуры и Markdown-файлов | Определить состав ДЗ и текущее состояние |
| `openssl zlib`, Perl | Временное извлечение текста из `homework.pdf` | Прочитать Backend-требования без установки PDF-инструмента |
| Git 2.53.0 | Создание и корректировка первого коммита | Зафиксировать исходное состояние |
| `apply_patch` | Точечное изменение Markdown-файлов | Записать утверждённую спецификацию и правила |
