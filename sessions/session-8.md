## Размышления

Проверка конкурентности внутри одного PHP-процесса не докажет корректность `flock`.
Поэтому тест запускает несколько отдельных PHP-процессов, каждый из которых создаёт
задачу через основной `JsonTaskStore`.

Тесты выполняются от привилегированного пользователя, поэтому `chmod 000` не даёт
надёжной ошибки доступа. Вместо этого файловые сбои моделируются структурно:
родительский путь делается обычным файлом для ошибки lock, а целевой путь —
каталогом для ошибки atomic rename. Эти случаи воспроизводимы и не зависят от UID.

Первый запуск конкурентного unit-теста упал до создания процессов: `base_path()`
требует Laravel Application, которого нет в чистом PHPUnit `TestCase`. Это была
ошибка инфраструктуры теста, а не store. Путь к fixture заменён на вычисление через
`__DIR__`, после чего 12 параллельных PHP-процессов завершились успешно: сохранены
все задачи, ID уникальны и последовательны, `next_id` равен 13.

Файловые тесты подтвердили, что ошибка создания lock и ошибка `rename` возвращают
безопасный `500 storage_error`, целевой файл/каталог сохраняется, временные файлы
убираются. Повреждённый JSON при запросе несуществующего ID возвращает
`storage_corrupted`, а не ложный `404`.
