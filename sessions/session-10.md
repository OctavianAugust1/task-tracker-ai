## Размышления

Текущий `JsonTaskStore` одновременно содержит правила задач и файловый I/O, а
контроллер напрямую вызывает его. Это не соответствует запрошенному разделению.
Целевая цепочка: versioned route → controller → service → repository interface →
JSON repository. Контроллер оставляет только HTTP-преобразование, сервис — правила
создания, сортировки, фильтрации и идемпотентного изменения, репозиторий — lock,
чтение, проверку структуры и атомарную запись файла.

`TESTS_INSTRUCTION.md` написан для Laravel 9/PHPUnit 10.5, тогда как проекту
запрещено менять Laravel 12/PHPUnit 11. Применяются совместимые правила документа:
AAA, русские PHPDoc-описания, Mockery и `CoversClass` для unit-тестов сервиса,
полный стек без моков в feature-тестах, `Http::preventStrayRequests()` и отдельный
временный JSON-файл. `DatabaseTransactions` неприменим и противоречит прямому
запрету базы данных; вместо транзакционного отката каждый тест изолируется своим
временным каталогом. Infection не добавляется: это новая зависимость, а запрос
требует переписать тесты, не внедрять mutation testing.

Версионирование меняет утверждённый публичный контракт. Поскольку пользователь
прямо потребовал его добавить, планируется единственный префикс `/api/v1/tasks`;
старые `/api/tasks` не сохраняются, чтобы по-прежнему было ровно пять endpoint'ов.
Перед кодом подготовлен отдельный план для человеческой проверки.

Пользователь уточнил расположение реализации. Подтверждено, что основное
приложение находится в `/workspace`, а `naive-run/` остаётся неизменяемым
сравнительным прогоном. После явного принятия плана рефакторинг выполнен в корне.

Для сохранения атомарности update сервис передаёт бизнес-преобразование callback'ом
в репозиторий. Репозиторий исполняет его внутри единого exclusive lock и решает,
нужна ли физическая запись. Вариант `service.find()` → `repository.update()` был
сначала реализован, но отвергнут при самопроверке: два отдельных lock оставляли бы
окно lost update при конкурентных запросах.

`JsonTaskStore` разделён на `TaskService`, интерфейс `TaskRepository` и
`JsonTaskRepository`. Файловые тесты сначала механически оказались в `tests/Unit`,
но независимый аудит указал, что реальные файлы и процессы делают их
интеграционными. Они перенесены в `tests/Feature`; только сервис тестируется в
полной изоляции с Mockery.

Тот же аудит обнаружил шаблонные русские PHPDoc, которые формально были русскими,
но не описывали сценарии, неверное имя idempotent-теста и неполный `CoversClass`.
Все замечания исправлены: каждый комментарий теперь называет конкретное поведение,
имя соответствует expectation, а metadata показывает всю feature-цепочку.
Точечный повторный аудит не нашёл новых Critical/Important. Старый Minor-gap
short write остаётся: защита в production-коде есть, но реалистичная симуляция
частичной системной записи потребовала бы отдельного filesystem seam.

Реальный сервер подтвердил POST `/api/v1/tasks` → 201, список → 200 и старый
`/api/tasks` → безопасный 404. Использовался отдельный временный каталог; после
остановки сервера он удалён, рабочий JSON не создан.

| отдельный агент-ревьюер | Проведены read-only аудит и точечная перепроверка исправлений | Получить независимую оценку архитектуры и тестов |
