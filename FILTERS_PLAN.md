# План комбинированной фильтрации

## Требуется согласовать

1. Формат нескольких статусов:
   - рекомендуемый: `statuses[]=todo&statuses[]=done`;
   - альтернативный: `status=todo,done`.
2. Смысл даты окончания:
   - рекомендуемый: точное совпадение `due_date=YYYY-MM-DD`;
   - альтернативы: `due_before`/`due_after` либо диапазон дат.
3. Совместимость старого `status=todo`:
   - рекомендуемый вариант: заменить его новым `statuses[]`, поскольку API v1 ещё
     учебный и dual input усложняет строгий контракт;
   - альтернативный: временно поддерживать оба формата, запрещая их сочетание.

## Рекомендуемый контракт

```text
GET /api/v1/tasks?statuses[]=todo&statuses[]=done&due_date=2026-08-20
```

- статусы объединяются через OR;
- дата объединяется со статусами через AND;
- дата означает точное совпадение;
- `due_date: null` не совпадает с заданной датой;
- одинаковые, пустые, неизвестные статусы, невалидная дата, неизвестные параметры
  и пустой `statuses[]` возвращают общий 422;
- без query-параметров возвращаются все задачи по `id`.
